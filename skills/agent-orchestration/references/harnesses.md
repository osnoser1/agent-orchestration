# Harnesses

Choose only models returned by the active harness's discovery step. If a harness cannot pick a model per subagent, run with its default and report that.

## Delegation surface

- **Default (`subagent`)**: delegate as a child task in the current project/checkout so results return to the orchestrator.
- **New top-level conversation (`conversation`)**: open a separate top-level conversation when the work belongs to a different project/repo than the current one, the user should follow or steer it directly, it is long-lived with its own PR lifecycle, or it would bloat the orchestrator's context. Apply the same brief template and model selection, and link the report back to the originating conversation. These conversations send no completion wakeup, so they fall under the supervision loop (`references/supervision.md`).
- **Authorization**: governed by `preferences.new_conversations: ask|allow` in `assets.yaml` (default `ask`: ask once per `SKILL.md` Step 7, then proceed) and any `Conversations:` line in repo policy (`references/repo-policy.md`). Switching an existing child's model in place, scheduling a resume, and running recurring supervision checks over non-notifying children inside the same conversation stay on the current thread and run under routine orchestration (`SKILL.md` Step 7). Active harness rules remain authoritative.

## Quota recovery: switch in place, new child, or scheduled resume

When a running child (implementer or reviewer) hits a quota limit, follow this exact decision order (no overlap):

1. **Record and re-select**: persist the lockout and get the next step in one call with `scripts/orch.py exhaust <provider> "<error>" --complexity <c> --risk <r> --available <provider:model,...> --ref <ref>` (add `--model` or `--group` per `references/quota-errors.md`, and `--role reviewer --implementer <model-id>` for a reviewer), log `--outcome quota` (`scripts/orch.py log`), and follow its `action:` line (quota pools and `preferences.below_tier` in `references/selection.md`).
2. **Candidate exists and harness can switch model in place**: a candidate from a `low` or `preserve` pool counts (`references/selection.md`). Switch the existing child's model so it keeps its full context (see **Switch model in place** below). When `exhaust`/`select` returns a `stage:` action, switch only a child whose remaining work is Phase 1 preparation; the `stage` phase-boundary switch onto an exhausted target follows `references/selection.md`. After switching, read the child's state (`t3_thread_read` / task status in T3 Code, or the harness's equivalent):
   - If a turn is already running or queued on its own, send nothing (an extra message starts a duplicate turn).
   - If the child is idle, send one short message (passing an idempotency key derived from the child's last observed turn/message ID when supported, `references/supervision.md`): `"continue from where you stopped; re-run any interrupted command in the foreground"`.
   Log the continuation selection (`scripts/orch.py log --event select`).
3. **Candidate exists and harness cannot switch model in place**: cancel the old child and confirm it stopped first (`references/supervision.md`), then start a new child on the same `surface` with the original brief plus partial results (branch/commit/worktree and last completed step) and log the continuation selection.
4. **No usable candidate (`exhaust`/`select` exits `4`), a `STAGE` plan for a child already past preparation, or a `stage` Phase 2 double check**: keep emergency and pay-per-use models excluded; they run only after the one approval in `SKILL.md` Step 7. Keep one pending resume in `assets.yaml`: `exhaust … --ref <ref>` in step 1 already recorded it; otherwise record it with `orch.py followups --add --kind resume --ref <ref> --needs <tier> --after <earliest_reset + 2m> --on-recovery` (deduplicated per `ref` so later conversations skip duplicate scheduling). If the harness supports delayed scheduling (see **Scheduled resume** below), schedule one resume at `earliest_reset + 2m` for the same child conversation and inform the user once; at wakeup it re-reads the child, derives the idempotency key from the turn observed then, and sends only while the child is idle. Without a scheduler, report the earliest reset time to the user. Clear the follow-up with `orch.py followups --done <ref>` when the child resumes.
5. **Gate stop (`exhaust`/`select` exits `3`)**: follow the `action:` line. `ask the user once` (`ASK`, emergency, or pay-per-use under `ask`): ask once (`SKILL.md` Step 7) and apply the answer. `hold until` (`DEFER`): wait like step 4 using the time in the action. `rerun select without --fail-on-low`: do so, since a low pool never holds work (`references/selection.md`). `no usable model`: report it to the user.

*Done when*: the lockout and outcome are logged, and the child is running on a usable model, waiting on one recorded `resume` follow-up with its wakeup scheduled (or its reset time reported), or waiting on the user's answer to one question.

## Orchestrator's own quota

Keep coordinating on a usable model when the orchestrating conversation's own pool reaches `low` or is exhausted — select replacements through the orchestrator ladder in `references/selection.md` (`select --role orchestrator --coordination <0|1|2>`):

1. **Low threshold (before a forced stop)**: run `scripts/orch.py select --role orchestrator --coordination <0|1|2> --ref orchestrator-self` (this conversation's `coordination` score from the `references/selection.md` rubric) with the orchestrator's `low` pool omitted from `--available`. Switch now only on a `launch the orchestrator on …` action; on `hold until`, `ask`, `no usable model`, or `no tier match`, keep coordinating on the `low` pool and clear the entry with `scripts/orch.py followups --done orchestrator-self`.
2. **Exhausted (if this conversation can still run commands)**: run `scripts/orch.py exhaust <provider> "<error>" --self --coordination <0|1|2> --available <provider:model,...> --ref orchestrator-self` (add `--model` or `--group` per `references/quota-errors.md`) and follow its `action:` line; clear `orchestrator-self` with `scripts/orch.py followups --done orchestrator-self` after a resume completes. When the harness already halted the turn on quota, switch or hand off on resume (or from a fresh conversation carrying durable state, `references/supervision.md`) using the target from the last `select` or `exhaust --self` `action:` line.
3. **Switch in place or hand off**: when `select`, `exhaust --self`, or `escalate --role orchestrator` names a target:
   - **Harness can switch this conversation**: apply its **Switch model in place** cell below. On T3 Code, call `t3_thread_configure` omitting `threadId` with the target `modelSelection`, then call it with no arguments to read this thread's effective `modelSelection` (**verified**) and convert it to `provider:model@effort` (`references/orchestrator-launch.md`, step 1). Log both with `scripts/orch.py log --event select --role orchestrator --surface conversation --complexity <c> --risk <r> --provider <p> --model <m> --effort <e> --rubric <rubric> --requested <target P:M@E> --effective <read P:M@E> --ref <item>`, where `--provider/--model/--effort` are the target. Handle a `warning: effective … differs` line, or a harness that cannot report the effective model, per `references/orchestrator-launch.md`, step 3.
   - **Harness cannot switch its own model**: give the user the command from the harness's **Switch model in place** cell when that command can select the target model (e.g. Claude Code `/model` within Anthropic models); otherwise hand off durable state to a new conversation launched from a `role: orchestrator` spec with `scripts/orch.py launch <spec>` (`references/orchestrator-launch.md`; follow `SKILL.md` Step 7 for `preferences.new_conversations`).
4. **Nothing usable (`hold until <time>`)**: schedule this conversation's resume at `earliest_reset + 2m` per the **Scheduled resume** column (or report the reset time when no scheduler exists) and refresh durable state (`references/supervision.md`).

*Done when*: this conversation has switched to a usable model with its effective model/effort verified and logged (or handed off via the harness's **Switch model in place** command or an `orch.py launch` conversation with durable state), kept coordinating on a `low` pool after clearing `orchestrator-self` when `select` did not return `launch the orchestrator on …`, or scheduled one resume (or reported its reset time) after `exhaust --self` printed `hold until`.
