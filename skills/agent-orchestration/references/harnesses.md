# Harnesses

Choose only models returned by the active harness's discovery step. If a harness cannot pick a model per subagent, run with its default and report that.

## Delegation surface

- **Default (`subagent`)**: delegate as a child task in the current project/checkout so results return to the orchestrator.
- **New top-level conversation (`conversation`)**: open a separate top-level conversation when the work belongs to a different project/repo than the current one, the user should follow or steer it directly, it is long-lived with its own PR lifecycle, or it would bloat the orchestrator's context. Apply the same brief template and model selection, and link the report back to the originating conversation.
- **Authorization**: governed by `preferences.new_conversations: ask|allow` in `assets.yaml` (default `ask`: ask once per request, then proceed) and any `Conversations:` line in the target repo's `## Orchestration` (`references/repo-policy.md`). Active harness rules remain authoritative.
