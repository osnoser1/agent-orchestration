# Quota probes, thresholds, and error parsing

## Automatic probe (`scripts/orch.py probe`)
Run `python3 scripts/orch.py probe` during discovery to refresh `used_percent`, `window`, `resets_at`, and per-group `groups` in `assets.yaml`. With no `assets.yaml`, `probe` reports against defaults and leaves the file uncreated; `probe --init` creates it.
- **Probe sources**:
  - **Antigravity**: `agy -p "/usage" --output-format json < /dev/null` (zero-token cost; requires one-time sign-in in the interactive `agy` TUI). Parses `command.data.groups[]` (`used_percent = 100 - remaining_fraction * 100`), ignores `disabled` buckets and expired `reset_time` windows, takes each group's most constraining active bucket, maps display names to catalog ids (unmatched kept as-is and reported once), persists `groups`, and sets provider `status` to the best group (`ok` when any group is usable).
  - **Claude**: `GET https://api.anthropic.com/api/oauth/usage` using local OAuth tokens from `<config_dir>/.credentials.json` (sent only to that endpoint, omitted from stdout, logs, `assets.yaml`, and the usage cache). Missing credentials or HTTP 401 report `unverified` and continue. Sessions share one usage cache (`usage-cache/` next to `assets.yaml`, also when that file is absent): `probe` reuses a reading younger than `preferences.usage_cache_ttl_seconds` (default 300), and `probe --fresh` requests a new one. After HTTP 429, `probe` sends no request until `Retry-After` (default 600 s) passes and reports `unverified` with the last known value; treat the provider as unverified.
  - **Codex**: latest `token_count` event in today + yesterday `$CODEX_HOME/sessions/YYYY/MM/DD/rollout-*.jsonl` (`payload.rate_limits.{primary,secondary}`), skipping expired windows.
- **Thresholds**: `used_percent >= 85` marks `status: low` (override via `preferences.low_threshold` or `--low-threshold`); `used_percent >= 98` marks `status: exhausted` with `exhausted_until: <resets_at>` (override via `preferences.exhausted_threshold` or `--exhausted-threshold`; `0 < low_threshold <= exhausted_threshold <= 100`; applied per group when a provider reports `groups`).
- **Precedence and merge with error-derived lockouts**: `probe` merges probed usage into existing provider and `groups` entries rather than overwriting them. When `probe` and an error lockout disagree, an unexpired `exhausted_until` from `orch.py exhaust` (at provider or group level) takes precedence over a `probe` reporting `< exhausted_threshold` unless the probe shows that same scope recovered (usage at `0%` / `reset`, lower `used_percent` than before the lockout, or a later `resets_at` for the same window). On a provider split into groups, a provider-level lockout clears as soon as any group shows that recovery, and the provider `status` then summarizes its groups. Conversely, `used_percent >= exhausted_threshold` in `probe` marks that scope `exhausted` immediately.
- **Auto-recovery**: any `exhausted` provider or group whose `exhausted_until` or `resets_at` has passed clears once per expired scope, persists to `assets.yaml`, and prints one recovery line; a grouped provider whose groups are still exhausted stays `exhausted` with the earliest group reset as its new `exhausted_until`. `probe` also surfaces `followups` per `references/selection.md` (`due` only when `--available` includes a usable match, otherwise `pending`).
- **Exit codes (`orch.py`)** (only the final `action:` line carries the decision; follow it instead of reading exit codes): `0` ok (including a `STAGE` plan, provisional selection, or an allowed `defer` hold/queue/ask) · `1` validation/usage error · `2` no tier match (`select` / `exhaust` with selection args) · `3` blocked by pre-flight threshold or policy gate (`low` ≥`low_threshold`, gated, or `ui_fallback: defer|ask`) · `4` quota hit (`exhausted` / ≥`exhausted_threshold`, or `select` / `exhaust` waiting on an exhausted tier-meeting model or reviewer) · `5` `defer` refused (a usable model exists; dispatch or stage now). `escalate` exits `2` when no higher rung exists and `3` at its cap or when it asks the user (`references/supervision.md`).

## Reactive error parsing (`scripts/orch.py exhaust`)
Trigger on messages containing `"hit your (weekly|usage) limit"`, `"quota reached"`, `"rate limit"`, `"try again at"`, or `"resets"`:

| Message | Parse | Write |
|---|---|---|
| `You've hit your weekly limit · resets Nov 23, 3am (America/New_York)` | absolute date + IANA zone | `exhausted_until: 2026-11-23T03:00:00-05:00` |
| `Quota limit reached · resets Nov 23, 3am (America/Argentina/Buenos_Aires)` | multi-segment IANA zone | `exhausted_until: 2026-11-23T03:00:00-03:00` |
| `Individual quota reached… Resets in 4h29m1s` / `Resets in 2 hours 30 minutes` | relative duration | `now + duration` |
| `You've hit your usage limit… try again at Nov 26th, 2026 8:01 AM` | absolute (local tz if omitted) | `2026-11-26T08:01:00<tz>` |
| `Weekly limit resets Dec 1` / `resets 2026-12-01` | date-only | end of that day (`23:59:59`) |

Rules:
- Missing year resolves to the next future occurrence; missing time resolves to `23:59:59` of that day; unparseable messages default to `now + 1h` with `unparsed: true`.
- Scope: on a provider whose quota is split into groups (Antigravity, or any provider whose `groups` come from a usage probe and carry a `window`), pass `--model <id>` for the model that hit the limit (mapped to its group via `groups[].models` and `catalog.yaml`) or `--group <name>`; `exhaust` marks only that group (`status: exhausted`, `exhausted_until`, `status_note`) and recomputes the provider's summary `status`. Without either flag it exits `1` and lists the groups. On any other provider, `--model <id>` records a per-model cap (e.g. a top model's weekly limit) as that model's own one-model group, one per capped model, and leaves the account status untouched; without `--model`, `exhaust` locks the whole account. Update top-level `updated`, then resume work on the next candidate per `references/harnesses.md`.
